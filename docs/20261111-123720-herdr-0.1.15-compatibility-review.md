# Herdr 0.1.15 변경 및 Files Workspace 호환성 검토

## 1. 목적과 범위

- 검토일: 2026-11-11 (Asia/Seoul)
- 비교 버전: Herdr 0.1.14 → 0.1.15
- 설치된 버전: Herdr 0.1.15
- 목적: 신규 기능과 공개 API 변경을 확인하고, Files Workspace에 필요한 후속 작업을 판단한다.
- 제약: Herdr 본체는 수정하거나 다시 빌드하지 않는다. 확장 기능은 공개 모드 API로 구현한다.

이 문서는 검토 결과를 기록한다. 코드 변경이나 전체 기능의 동작 인증을 의미하지 않는다.

## 2. 결론

즉시 반영해야 하는 호환성 문제는 발견하지 못했다. Files Workspace와 헤더 모드의 검사 모두 통과했고, 실행 중 앱의 오류 목록도 비어 있었다.

새로운 `ScrollHandle`은 파일 트리에서 선택된 항목을 화면 안으로 이동시키는 데 활용할 수 있다. 내장 편집기의 커서 이동, Undo/Redo, 파일 시스템 조작을 위한 공개 API는 이번 버전에도 추가되지 않았다.

최소 지원 버전은 0.1.13을 유지한다. 0.1.15 전용 API를 도입할 때는 이전 버전에서 기존 동작을 유지할 수 있는지 확인해야 한다.

## 4. 공개 API 변경

### 4.1 일반 스크롤 영역의 ScrollHandle

새 API의 주요 형태는 다음과 같다.

```ts
interface ScrollHandle {
  scroll_to_item(index: number): void;
  release(): boolean;
}

const ScrollHandle: { new: () => ScrollHandle };
```

핸들을 생성한 뒤 일반 스크롤 요소에 `.track_scroll(handle)`로 연결한다. `scroll_to_item(index)`는 0부터 시작하는 직접 자식의 인덱스를 받는다. 항목이 이미 보이면 위치를 유지하고, 가려져 있으면 필요한 만큼 이동한다. 이동 요청은 레이아웃 계산 후 한 번 적용된다.

이 API는 내장 편집기 내부의 줄이나 커서에 접근하지 않는다. 외부 스크롤 영역에 핸들을 연결하는 것만으로 편집기 본문의 특정 줄로 이동할 수는 없다.

Files Workspace의 검색 결과 목록은 이미 `VirtualListScrollHandle`을 사용한다. 새 일반 스크롤 API로 교체할 필요가 없다. 파일 트리의 생성·복사·이동 후 선택 항목을 표시하는 기능이 더 적합한 활용 후보이다.

근거: [API 정의](https://github.com/herdrdev/herdr-app/blob/v0.1.15/vendor/gpui-kit/crates/shell/src/typings.rs), [스크롤 구현](https://github.com/herdrdev/herdr-app/blob/v0.1.15/vendor/gpui-kit/crates/shell/src/scroll.rs).

### 4.2 레이아웃의 toast 설정

루트 레이아웃에 `"toast": "모드 이름"`을 지정하여 알림 렌더러를 선택할 수 있다. 앱 알림과 `notify()`가 지정된 렌더러를 사용한다. 지정한 모드를 찾을 수 없으면 경고를 기록하고 기본 알림으로 돌아간다.

기존 `notify()` 호출은 유지할 수 있다. 현재 Files Workspace에서 별도 알림 렌더러를 도입할 필요는 없다.

근거: [모드 지침](https://github.com/herdrdev/herdr-app/blob/v0.1.15/defaults/AGENTS.md), [레이아웃 구현](https://github.com/herdrdev/herdr-app/blob/v0.1.15/src/layout.rs).

### 4.3 기존 API의 동작 변경

| API | 변경 내용 | 판단 |
| --- | --- | --- |
| `knownAgents()` | 검사 실패 시 모든 에이전트를 미설치 상태로 반환하지 않고 Promise를 거부한다. 실패 결과는 캐시하지 않는다. | 현재 모드는 호출하지 않으므로 수정이 필요 없다. |
| `terminals()` | 부모 터미널 주소를 앱의 머신 이름 기준으로 정규화한다. | 현재 기능은 해당 부모 주소에 의존하지 않는다. |

근거: [Herdr API 정의](https://github.com/herdrdev/herdr-app/blob/v0.1.15/defaults/herdr.d.ts), [모드 API 구현](https://github.com/herdrdev/herdr-app/blob/v0.1.15/src/mods.rs).

### 4.4 추가되지 않은 API

다음 기능은 여전히 공개 모드 API로 직접 연결할 수 없다.

- 내장 편집기의 Undo/Redo 호출.
- 내장 편집기의 커서·선택 범위 설정 및 특정 줄로 이동.
- PowerShell/Python을 대체할 폴더 조회·복사·이동·삭제 API.

`EditorState`의 공개 메서드는 `value`, `set_value`, `on`, `release`이며 이번 비교에서 변경되지 않았다. 내장 편집기의 단축키 지원 여부와 모드에서 호출할 수 있는 API의 존재 여부는 구분해야 한다.

기본 Files 모드도 이번 버전 비교에서 변경되지 않았다. 현재 확장 기능을 기본 Files 모드로 대체할 근거는 없다.

## 5. 반영 권장 사항

| 우선순위 | 항목 | 권장 조치 |
| --- | --- | --- |
| 선택 개선 | 파일 트리 자동 스크롤 | 생성·복사·이동 후 선택한 항목이 화면 밖에 있으면 새 `ScrollHandle`로 표시하는 방안을 검토한다. |
| 선택 개선 | 하단 헤더 구분선 | `files-workspace-header`의 고정된 아래쪽 구분선을 헤더 위치에 따라 바꾼다. 현재 상단 배치에는 문제가 없다. |
| 유지 | 검색 결과 스크롤 | 기존 `VirtualListScrollHandle`을 유지한다. |
| 유지 | 파일 시스템 처리 | 현재 PowerShell/Python 구현을 유지한다. |
| 보류 | Undo/Redo 버튼 및 검색 결과의 본문 이동 | 대응하는 공개 편집기 API가 제공된 뒤 연결한다. |

현재 헤더의 기본 컨트롤을 항상 표시하는 동작은 유지한다. 본체의 헤더 변경을 반영하더라도 사용자가 요청한 표시 방식을 되돌리지 않는다.

## 6. 최소 버전 관련 추가 확인 사항

새 `ScrollHandle`은 0.1.15에서 제공한다. 이를 사용하려면 API 지원 여부를 확인하고, 0.1.13 및 0.1.14에서는 기존 동작으로 돌아가야 한다. 이전 런타임에서 제공되지 않는 API를 무조건 가져오는 방식은 피해야 한다.

현재 파일 작업 코드의 장시간 복사용 `exec.timeout` 옵션은 0.1.14에서 추가됐다. 이는 0.1.15의 신규 문제는 아니다. 다만 0.1.13에서도 동일한 장시간 실행을 보장하려면 별도 호환성 검증이 필요하다. 이 검토만으로 0.1.13에서 모든 복사가 실패한다고 판단하지 않는다.

근거: [Herdr 0.1.14 변경 기록](https://github.com/herdrdev/herdr-app/blob/v0.1.14/CHANGELOG.md).

## 7. 검증 결과와 한계

| 확인 항목 | 결과 |
| --- | --- |
| 설치된 Herdr 버전 | 0.1.15 확인 |
| 소스 비교 | 공식 태그 `v0.1.14`와 `v0.1.15` 비교 |
| `files-workspace` 모드 검사 | 통과 |
| `files-workspace-header` 모드 검사 | 통과 |

| 전체 기능의 실제 조작 테스트 | 이번 검토에서는 수행하지 않음 |

검토용 클론의 작업 트리는 이전 버전일 수 있으므로 태그의 소스를 기준으로 비교했다. 모드 검사 통과와 오류 목록이 비어 있다는 사실만으로 모든 렌더링 및 파일 작업의 정상 동작을 보장하지 않는다.

이번 작업은 검토 자료 저장이다. Herdr 본체와 모드 코드는 변경하지 않았다. 기존 작업 중인 변경 사항을 보존했으며 커밋과 푸시는 수행하지 않았다.
